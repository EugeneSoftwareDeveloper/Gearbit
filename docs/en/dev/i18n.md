# Languages: Russian and English

[Русский](../../dev/i18n.md) · **English**

Everything the user sees exists in two languages: the interface, hub messages, Python and C# program errors, the window splash screen. The hub log, method descriptions in `hub.methods` and code comments stay in Russian: they are for the developer.

Texts for a child are short and clear, with a hint about what to do. The English text is written just as simply, not translated word for word.

## How the language is chosen

1. If the user picked a language in the settings (⚙ → **Language · Язык**), that one is used. It is stored in the hub's `settings.json` (`lang`), see [Hub API](hub-api.md#http).
2. Otherwise — by the system language: `ru`, `uk`, `be`, `kk` → Russian, everything else → English. In the interface it's `detectLang(navigator.languages)`, in the WPF window — `CultureInfo.CurrentUICulture`.

The language is chosen once when the page loads. Changing the language saves the settings and reloads the page (`setLang` in `i18n.ts`): program drafts are already in `localStorage` by then.

The interface passes the language to the hub in `hub.hello {lang}`. The hub answers this client in its language and passes the language to the program the client started (`GEARBIT_LANG`). A client without `lang` gets Russian texts.

## Interface (`web/studio-ui`)

Texts live next to the code that shows them:

```ts
import { lang, messages } from "../i18n";

const M = messages({
  ru: { stop: "СТОП", step: (n: number) => `Шаг ${n}` },
  en: { stop: "STOP", step: (n) => `Step ${n}` },
});

button.textContent = M.stop;
```

- `messages()` returns the dictionary of the page language. The `en` type is inferred from `ru`, so TypeScript won't build the project if `en` is missing a key or a function has different parameters. A separate completeness test isn't needed: `npm run typecheck`.
- `M` is evaluated when the module loads, so the language must be known before that. That's how it's done: `main.ts` first reads the settings (`syncSettings`), sets `document.documentElement.lang` and only then loads `app.ts`.
- Dates, times and sorting use `lang()`: `toLocaleTimeString(lang(), …)`, `a.localeCompare(b, lang())`.
- Language names in the switcher (`LANGS`) are always in those languages themselves.
- Blocks: our own blocks (`blocks/robot-blocks.ts`), categories (`blocks/toolbox.ts`) and examples (`blocks/examples.ts`) are in two languages. The standard blocks are translated by scratch-blocks: `SB.ScratchMsgs.setLocale(lang())`.
- Python and C#: completions, the **Commands** card and examples (`code/python.ts`, `code/csharp.ts`) are in two languages. In English examples the comments are English too.

## Hub (`src/Gearbit.Hub`)

- Texts are in `HubText.cs`: the `IHubText` interface and the `RuHubText`, `EnHubText` classes. Add a new text to the interface and to both classes — the project won't build without a translation.
- Each client has its own `Text` (from `hub.hello {lang}`).
- An error: `throw new HubException(HubErrors.NotFound, t => t.NoMotor(id))`. The exception `Message` is the Russian text for the log; the client gets the text in its own language.
- A notification with text goes through `ClientRegistry.BroadcastText`: each client gets it in its own language.
- Core and the BLE transport don't write user texts: `RobotException` carries a `RobotErrorCode`, and the hub shows `IHubText.RobotError` for it.
- The test goes into `HubTests`: the same call with `lang: "en"` and without `lang`.

## Window (`src/Gearbit.App`)

`AppText.cs`: the splash screen texts, the "WebView2 is needed" window and the "Port is busy" message. The language comes from `settings.json` (`lang`), otherwise from `CultureInfo.CurrentUICulture`.

## Python (`python/gearbit`)

- Texts are in `_texts.py`: the `RU` and `EN` dictionaries, `t("key", **params)`. Parameters go in `{curly braces}`.
- Language: `GEARBIT_LANG`, without it — the system language (`detect_lang`). Tests pin Russian: `set_lang("ru")`.
- The `test_texts.py` test checks that the keys and parameters in `RU` and `EN` match.

## C# (`Gearbit.Client`, `Gearbit.ScriptHost`)

- Client: `ClientText.cs` — the `IClientText` interface and two classes. The language is `ClientText.Current`: from `GEARBIT_LANG`, without it — from `CultureInfo.CurrentUICulture`.
- Script host: `ScriptText.cs` (`IScriptText`) — hints for Roslyn errors in `CompileErrors.cs` and `RuntimeErrors.cs`. The original Roslyn message is shown in the culture of the same language.
- A new robot command — its error text goes into both languages, in both Python and C#, right away.

## Descriptions of robots (`devices/`, `profiles/`)

Fields the user sees (the `title` of a build, model and component) are written as an object by language:

```json
"title": { "ru": "Машинка", "en": "Car" }
```

A plain string works too — it fits any language, so old and third-party descriptions don't break. In C# it's `LocalizedText`, the hub passes the field to the client as is, and the interface picks the language with the `text(title)` function from `i18n.ts`.

## Documentation

Russian documentation is the main one, English is a copy in `docs/en` ([rules](README.md#documentation-in-two-languages)). In English docs the interface labels are in English, as the English interface shows them.
